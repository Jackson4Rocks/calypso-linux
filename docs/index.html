01 · PHILOSOPHY

Less noise.
More intent.

Calypso is not meant to win by piling on software. The idea is a focused Arch-based system with a coherent visual identity, useful defaults, and room for the user to make it their own.

Fast + leanKeep the system focused on the essentials instead of treating extra software as a feature.
Choice without clutterDesktop choices should remain choices. Optional paths should not overpower the main experience.
One visual languageBranding, wallpapers, icons, documentation, and the website use the same emerald-and-obsidian direction.
Open developmentThe public repository contains the project layers, making the distro understandable and inspectable.
02 · INSTALLATION

Installation guide.

The live image is designed around a graphical installation flow. This section documents the current installation model rather than turning the wiki into a collection of command-heavy tutorials.

01

Boot the live environment.

Start the Calypso ISO in UEFI mode and reach the live desktop.

02

Choose the installation path.

The graphical installer provides the normal route from the live system to an installed Calypso desktop.

03

Set storage and account details.

The current project is designed around GPT, ext4 by default, user creation, locale and keyboard selection, and a standard system installation.

04

Boot the installed system.

The installed environment uses SDDM and systemd-boot on the current UEFI-oriented setup.

Important: always back up data before changing disk layouts. Installation choices can permanently affect the selected storage device.
03 · DESKTOP

A place to start,
not a box.

Calypso keeps the desktop layer flexible. KDE Plasma forms the main environment, while users who prefer tiling and keyboard-driven interaction can take the optional Hyprland route.

The important part is the choice itself: Calypso's identity does not depend on forcing every user into the same workflow.
MAIN DESKTOP

KDE Plasma

The broad, configurable desktop layer used for the primary Calypso experience, including panels, settings, applications, accessibility, and normal graphical workflows.

OPTIONAL WINDOW MANAGEMENT

Hyprland

An optional path for users who enjoy tiling, keyboard-driven interaction, and deeper compositor-level control. It remains separate so it does not define the whole distribution.

04 · OPTIONAL HYPRLAND

What lives
in dotfiles.

The Hyprland side of the project is maintained separately under dotfiles/. It can evolve faster than the core desktop without changing what Calypso is at its center.

COMPOSITOR

Hyprland

Window rules, keybindings, workspaces, focus behavior, monitor configuration, and compositor preferences.

DESKTOP SHELL

Quickshell

The optional profile uses Quickshell for its surrounding shell layer, such as panels, controls, and desktop UI.

THEMING

Matugen

Wallpaper-derived color generation can feed the shell and supporting applications for a unified look.

SUPPORTING TOOLS

Utilities

Depending on the configuration, the optional workflow can also include Kitty, Fastfetch, Fuzzel, Yazi, Hyprpaper, and Zsh.

Configuration boundary

Hyprland configuration is kept separate from the KDE-centered base experience.

Why separate it?

It lets the power-user layer evolve without making its preferences mandatory for everyone else.

Why make a distro?

Because building the whole thing is a different kind of learning: desktop design, boot systems, packaging, configuration, documentation, and user experience all meet in one project.

What is Calypso trying to become?

A polished, fast, understandable Linux distribution with a strong identity — without making the user give up the freedom that attracted them to Linux in the first place.
